# 0027 The cross-run record sits outside the simulation (decided)

Status: decided and implemented in milestone M15.

## Decision

- The chronicle is not part of any simulation's state or snapshot. The host folds a run's events
  into it and gives the next run what it needs through the configuration.
- The chronicle is saved on its own in an envelope: a magic, the envelope version, the message
  version and a checksum ahead of the payload. A save of another version, or a damaged one, is
  refused.
- A retired name stays retired for every later run.
- Control falls back to the first candidate the caller lists, never to the one just lost, and is
  vacant when none is left. The library does not choose the heir.
- A hire is an archetype's base plus whole points bought above it at stated costs, within one
  budget. Spending the budget exactly is allowed; nothing is refunded.

## Alternatives rejected

- The chronicle inside the snapshot: a new run starts from nothing, so it would not survive one.
- Bare bytes for a save: a changed shape reads as garbage instead of a refusal.
- Letting a run clear a retirement: a lost line would be cheap to forget.
- The library choosing the heir: the rule belongs to the game or business.
- Free-form values checked against a total, and refunds: neither says what an archetype is, and
  refunds make the order of purchases matter.

## Would change if

`crates/lockstep-meta/tests/decisions/` fails: a retired name is not retired after another run
begins or after a save; a save of another version or a damaged one opens; a transfer names the lost
entity or skips an earlier candidate; or a purchase costing more than the budget builds.
