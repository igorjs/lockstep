# 0004 Fixed-point math (decided)

Status: decided, implemented in milestone M3 (the math half; `lockstep-spatial` follows).

`lockstep_core::math` holds `Fixed32` (16.16), `isqrt`, `Vector2`, and angles as whole turns
(`Turn = u16`). Everything is integer arithmetic, so results are identical on every platform.

Decisions and where the reference was changed:
- **Integer CORDIC tables.** The quarter-turn sine table (4,097 entries) and the arctangent table (1,025 entries over tangents 0 to 1) are generated at compile time by integer CORDIC from hard-coded integer constants, and committed as `fixtures/quarter_sine.bin` and `fixtures/atan_octant.bin`. A test regenerates both and compares them. The sine is interpolated linearly between entries four turn units apart, because the table alone is up to 25 raw units off.
- **`abs` and negation wrap.** The reference used `i32::abs`, which panics in debug builds and wraps in release for the minimum value. Wrapping on both keeps debug and release identical.
- **`Vector2::length` works in 64 bits** on the raw components, so it stays correct for vectors where `x * x` would overflow 16.16. The reference squared in fixed point.
- **`Vector2::toward` truncates its step toward zero**, so it never moves farther than its step, never grows the distance, and arrives exactly. It takes the difference and the length in 128 bits, so two points on opposite sides of the range (more than 32,767 units apart on one axis) are handled exactly. A first version took the difference in fixed point, which wrapped and sent the walk the wrong way; the second review of the pull request found it, because the earlier tests measured distance with the same wrapping subtraction. A negative step counts as zero. A positive step always makes progress: when both scaled parts truncate to zero (a tiny step along a diagonal) it takes one raw unit along the longer axis.
- **`Vector2::length` and `distance` saturate** at the largest `Fixed32` instead of wrapping negative, for lengths over 32,767 units. `normalised` and `toward` use the exact 128-bit length internally.
- **`Fixed32::round` works in 64 bits**, so the values just under the top of the range round up to 32,768 instead of wrapping to minus 32,768. Ties round up (3.5 gives 4, minus 3.5 gives minus 3), which is the opposite mirror rule from `from_ratio`.
- **Division and `from_ratio` wrap on overflow**, like the other operators.
- **`Fixed32::from_ratio` rounds ties away from zero**, so a negative ratio is the exact mirror of the same positive one (`from_ratio(-1, 2)` is minus one half). The reference's formula rounded negative ties the wrong way.
- **The arctangent table needs 128-bit arithmetic** at generation time. A first version wrapped silently in 64 bits for tangents near one, and the round-trip test caught it.

These came out of two self-review passes of the pull request, which found the wrapping length, the wrapping difference, the negative-ratio rounding, the wrapping round, the negative step and the stalled diagonal step.

Measured: square roots are exact for every perfect square up to 180 squared and within one raw
unit on 100,000 samples; sin squared plus cos squared is within 8 raw units everywhere; the
arctangent returns every angle within 4 turn units and is within 1 turn unit of the true angle
(the requirement was 0.01 degrees, about 1.8 units).

Money (minor units with a currency exponent) belongs to milestone M16.
